# Правила работы в проекте Claude Brainrot

Этот файл действует для всего репозитория. Инструкции пользователя по текущей задаче имеют приоритет над правилами проекта. Более конкретные `AGENTS.md` в подпапках дополняют эти правила для соответствующих файлов.

## Общение и выполнение задач

- Общаться с пользователем на русском языке, коротко и по существу.
- Выполнять задачу до готового результата: изучить контекст, внести изменения, проверить их и сообщить результат.
- Перед началом работы читать существующие инструкции и относящиеся к задаче файлы.
- Уточнять только существенные неизвестные; обычные обратимые решения принимать самостоятельно.
- Не запрашивать повторное разрешение на уже согласованные действия.
- В длительных задачах кратко сообщать о ходе работы и возникающих препятствиях.
- Не выдавать предположения за факты и не утверждать, что проверка прошла, если она не выполнялась.
- Использовать субагентов только по явному запросу пользователя или применимой инструкции проекта.

## Изменения в проекте

- Вносить только изменения, необходимые для задачи; следовать принятой архитектуре и стилю.
- Не перезаписывать и не откатывать чужие незакоммиченные изменения.
- Не добавлять зависимости, абстракции и большие рефакторинги без необходимости.
- Не выбирать технологический стек до появления требований к приложению.
- Обновлять документацию при изменении установки, запуска, конфигурации или поведения.
- Держать этот файл актуальным: фиксировать подтверждённые команды и договорённости по мере развития проекта.

## Git и безопасность

- Постоянное правило: не указывать ИИ в AUTHORS/CONTRIBUTORS, авторах и соавторах коммитов, сопровождающих, ревьюерах или коммиттерах.
- Не добавлять трейлеры `Co-Authored-By` с ИИ и подписи агентов в коммиты или PR.
- Не менять `git config user.name` и `git config user.email`. Не переписывать историю для сокрытия или подделки авторства.
- Не указывать ИИ как участника проекта в метаданных.
- Основная ветка — `main`.
- Перед коммитом проверять `git status` и diff, включая подготовленные изменения.
- Добавлять в коммит явно выбранные файлы, проверенные в рамках текущей задачи.
- Писать короткие содержательные сообщения коммитов; рекомендуемые префиксы: `feat:`, `fix:`, `docs:`, `chore:`.
- Создавать коммиты, пушить, сливать ветки и публиковать результаты только в рамках разрешённой пользователем задачи.
- Не выполнять force push, переписывание общей истории, удаление веток или файлов без явного основания и согласования.
- Не коммитить токены, пароли, ключи, `.env`, личные данные, локальные настройки и временные артефакты.
- Примеры настроек хранить в `.env.example` только с безопасными заглушками.
- Не выводить секреты в логи, ответы или документацию.

## Инструменты и проверка

- Все временные файлы и рабочие артефакты хранить только в папке `.TMP` внутри проекта (`<project>/.TMP`): черновики, логи, выгрузки, скриншоты, промежуточные результаты и вспомогательные скрипты.
- Не использовать системную временную папку или каталоги вне проекта для таких файлов. Создавать `.TMP` при необходимости; её содержимое не коммитить. Исходники и постоянную документацию хранить в структуре проекта.
- Рабочая среда: Windows, PowerShell. Использовать совместимые команды и точные пути.
- Для поиска файлов и текста предпочитать `rg` и `rg --files`, если они доступны.
- Перед рекурсивным удалением или перемещением проверять абсолютный целевой путь.
- После изменений запускать подходящие существующие проверки: тесты, линтер, сборку — по характеру задачи.
- Добавлять тесты для значимого поведения и исправленных ошибок; избегать тестов, повторяющих реализацию.
- Если проверка недоступна, явно указывать причину и оставшиеся ограничения.
- В итоговом ответе указывать результат, выполненные проверки и существенные ограничения.
